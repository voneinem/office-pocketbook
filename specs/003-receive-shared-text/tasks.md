# Tasks: Receive Shared Text

**Input**: Design documents from `/specs/003-receive-shared-text/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md); constitution v1.2.0

**Tests**: REQUIRED. Constitution Principle I (Test-First, NON-NEGOTIABLE): in every group the test tasks come first and MUST be observed failing (the explicit "RED" task) before the implementation tasks; no change is merged while a test fails.

**Organization**: setup, the Qt-free core (foundation), then the user stories in priority order (US1, US2, US3 = P1; US4 = P2), then polish. The increments of `plan.md` map to phases as follows: increment 1 = Phases 1-3 and 5-6 (cold start, privacy, odd input; US2's host-testable rules are in Phase 4A), increment 2 = Phase 4B-4C (running instance, gated by the device experiments E1/E2), increment 3 = Phase 7. **User Story 3 (privacy) is a release gate** (FR-017): it is not optional and ships with User Story 1.

## Format: `- [ ] T### [P] [US#] [TAG] Description with file path`

- **[P]**: can run in parallel with its neighbours (different files, no dependency on an unfinished task)
- **[US#]**: the user story of `spec.md` (only in story phases)
- **Environment tags** (the default is *host-only*: Linux x86-64, no device, no real account, no SDK):
  - **[DEVICE]**: needs the PocketBook InkPad One. Cannot be completed by an agent or in CI; its result stays *unverified* until a date and a value are recorded (Principle IX). Follow the owner's procedure: install only after the owner says "mounted" / "Install!", the owner ejects, tests and says "mounted" again so the log can be read; fixed test strings only, no personal content; never touch PB Notes or InkFeed files; never run the host app against a copy of the reader's database.
  - **[SDK]**: needs the PocketBook SDK on the build machine (`POCKETBOOK_SDK`, never hard-coded) but not the device.
  - **[B1] / [B2] / [B3]**: conditional on the result of the device experiments E1/E2 ([research R-05](research.md)); do **only** the branch that task T035 records as selected.
- File paths follow `plan.md` ("Project Structure"). Every new `core/src/*.cpp` is added to `PBO_CORE_SOURCES` in `core/CMakeLists.txt`; every new bridge source to `PBO_BRIDGE_SOURCES` and every new bridge header to `PBO_BRIDGE_HEADERS` (and, when it has `Q_OBJECT`, to `PBO_BRIDGE_MOC_HEADERS`) in `bridge/CMakeLists.txt`; every new QML file to `qml/qml.qrc`; `tests/unit|contract|integration/test_*.cpp` register themselves by glob; bridge tests get their own block in `tests/CMakeLists.txt` (copy the `test_compose_bridge` block: `add_executable`, `target_link_libraries(... pbo_bridge Qt6::Core Qt6::Test OpenSSL::SSL OpenSSL::Crypto Threads::Threads)`, `target_include_directories(... support)`, `add_test`, `LABELS "bridge"`, `QT_QPA_PLATFORM=offscreen`) and their name to the `PBO_SANITIZE` `foreach` list at the end of that file; QML flow tests copy the `test_calendar_flow` block; launcher shell tests are one `add_test(NAME ... COMMAND ...)` line next to `launcher_script`.
- **Fixtures** are anonymized (fictional people, reserved example domains such as `example.org`, `*.invalid`), carry the `.unverified` marker in the file name when they imitate what the system delivers, and pass `scripts/check-fixtures.sh`.
- **Contract text is part of the task**: limits and rules quoted from `research.md` R-07, `data-model.md` and `contracts/` must be copied into code and tests, not paraphrased.
- **No test or code may write a handed-over value to a log, a notice or a file other than the draft and the pending entry.** Tests use a unique marker word (for example `PBO-MARKER-7f3a`) in the text, subject and recipient to prove it.
