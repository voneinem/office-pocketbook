# Tasks: Email and Calendar MVP (office-pocketbook)

**Input**: Design documents from `/specs/001-email-calendar-mvp/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md); constitution v1.0.0

**Tests**: REQUIRED. Constitution Principle I (Test-First, NON-NEGOTIABLE): in every group the test tasks come first and MUST be observed failing (the explicit "RED" task) before the implementation tasks; no change is merged while a test fails.

**Organization**: setup and foundations, then the user stories in priority order (US1, US2 = P1; US3, US4 = P2; US5, US6 = P3), then polish. Inside every story: core tests -> core library -> bridge tests -> bridge -> QML tests -> QML pages -> live/device checks. The walking skeleton (3A) is the first thing built inside US1.

## Format: `- [ ] T### [P] [US#] [TAG] Description with file path`

- **[P]**: can run in parallel with its neighbours (different files, no dependency on an unfinished task)
- **[US#]**: the user story of `spec.md` (only in story phases)
- **Environment tags** (the default is *host-only*: Linux x86-64, no device, no real account, no SDK):
  - **[DEVICE]**: needs the PocketBook InkPad One. Cannot be completed by an agent or in CI; its result stays *unverified* until a date and a value are recorded (Principle IX).
  - **[LIVE]**: needs a real mail or calendar server/account (Dovecot, Gmail, Outlook.com, the author's provider, Nextcloud/OpenCloud). Same rule: *unverified* until recorded.
  - **[SDK]**: needs the PocketBook SDK on the build machine (`POCKETBOOK_SDK`) but not the device.
- File paths follow `plan.md` ("Project Structure"). Every new `core/src/*.cpp` is added to `PBO_CORE_SOURCES` in `core/CMakeLists.txt`; every new bridge header is added to the HOST and ARM (manual moc) lists in `bridge/CMakeLists.txt`; every new QML file to `qml/qml.qrc`; `tests/unit|contract|integration/test_*.cpp` register themselves by glob, bridge and QML tests are listed in `tests/CMakeLists.txt`.

### Rules that apply to every task

- Test first, observe RED, then implement (Principle I). Boundary changes need a contract test in the same change.
- A user action is persisted before any network call; no sync step leaves a half state (Principle III).
- Never add TLS bypasses, plaintext fallbacks, remote-content loading, or personal data in logs (Principles IV, VI; checks R1-R9).
- Hand-written server transcripts carry `.unverified`; behavior that needs the device or a live server is labelled *unverified* until its `[DEVICE]`/`[LIVE]` task records a result (Principle IX).
- Commit after each task or logical group; end commit messages with the attribution lines required by the session.
