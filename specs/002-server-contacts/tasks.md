# Tasks: Server Contacts

**Input**: Design documents from `/specs/002-server-contacts/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md); constitution v1.2.0

**Tests**: REQUIRED. Constitution Principle I (Test-First, NON-NEGOTIABLE): in every group the test tasks come first and MUST be observed failing (the explicit "RED" task) before the implementation tasks; no change is merged while a test fails.

**Organization**: setup and foundations, then the user stories in priority order (US1 = P1; US2, US3, US4 = P2; US5, US6 = P3), then polish. Inside every story: core tests -> RED -> core library -> GREEN -> bridge tests -> bridge -> QML tests -> QML pages -> checkpoint. The increments of `plan.md` map to phases as follows: increment 1 = Phases 1-2, 2 = Phase 3 (US1), 3 = Phases 4-6 (US2-US4), 4 = Phases 7-9 (US5, US6, polish).

## Format: `- [ ] T### [P] [US#] [TAG] Description with file path`

- **[P]**: can run in parallel with its neighbours (different files, no dependency on an unfinished task)
- **[US#]**: the user story of `spec.md` (only in story phases)
- **Environment tags** (the default is *host-only*: Linux x86-64, no device, no real account, no SDK):
  - **[DEVICE]**: needs the PocketBook InkPad One. Cannot be completed by an agent or in CI; its result stays *unverified* until a date and a value are recorded (Principle IX).
  - **[LIVE]**: needs a real contact server (Nextcloud first, OpenCloud second). Same rule: *unverified* until recorded.
  - **[SDK]**: needs the PocketBook SDK on the build machine (`POCKETBOOK_SDK`) but not the device.
- File paths follow `plan.md` ("Project Structure"). Every new `core/src/*.cpp` is added to `PBO_CORE_SOURCES` in `core/CMakeLists.txt`; every new bridge source to `PBO_BRIDGE_SOURCES` and every new bridge header to `PBO_BRIDGE_HEADERS` (and, when it has `Q_OBJECT`, to `PBO_BRIDGE_MOC_HEADERS`) in `bridge/CMakeLists.txt`; every new QML file to `qml/qml.qrc`; `tests/unit|contract|integration/test_*.cpp` register themselves by glob, bridge tests get their own block in `tests/CMakeLists.txt` (copy the `test_event_edit_bridge` block: `add_executable`, `target_link_libraries(... pbo_bridge Qt6::Core Qt6::Test ...)`, `add_test`, `LABELS "bridge"`, `QT_QPA_PLATFORM=offscreen`) and their name to the `PBO_SANITIZE` `foreach` list at the end of that file; QML flow tests copy the `test_calendar_flow` block.
- **Fixtures** are anonymized (fictional people, reserved example domains such as `example.org`, `*.invalid`), carry the `.unverified` marker in the file name when they imitate a server, and pass `scripts/check-fixtures.sh`.
- **Every test that includes `fake_carddav_server.h` calls `PBO_FAKE_SERVER_TEST()`** (`scripts/check-fake-markers.sh`).
- Constraint text quoted from `data-model.md` and `contracts/` is part of the task: do not paraphrase it in code or tests.

## Implementation Strategy

### MVP first = User Story 1

1. Phases 1 and 2 (the refactor and schema are the risky steps: keep every existing test green, and look at the migration test results before going on).
2. Phase 3 (US1): stop and run `scripts/run-host-demo.sh`; a read-only address book works end to end on the host. This is the first demo and the smallest useful result (device and live-server results stay *unverified*).
3. Add the P2 stories in order: create (US2), edit (US3), delete (US4); then the P3 stories (US5, US6) and Phase 9.
4. The owner tests on the reader only after the host work of a story is green and the owner says "Install!"; the schema upgrade (T112 / DT-CT-1) is the only irreversible step: do it with the backup in place.

### Rules that apply to every task

- Test first, observe RED, then implement (Principle I). Boundary changes (CardDAV requests, vCard text, schema) need a contract or migration test in the same change.
- A user action is persisted before any network call; the pull never touches a row with local work; no sync step leaves a half state (Principle III).
- Never add TLS bypasses, plaintext fallbacks, remote-content loading, links that call or mail from a contact, or personal data in logs (Principles IV, VI; checks R1-R9).
- Hand-written server transcripts and fixtures carry `.unverified`; behaviour that needs the device or a live server is labelled *unverified* until its `[DEVICE]`/`[LIVE]` task records a result (Principle IX).
- Documentation, comments, identifiers, test names and commit messages are English (Principle X); German appears only in `qml/strings_de.tsv` and in explained test data.
- Mark a task `[X]` in this file when it is done and its tests pass.
- Commit after each task or logical group only when the owner asks; end commit messages with the attribution lines required by the session.
